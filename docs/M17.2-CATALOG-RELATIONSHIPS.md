# ReleaseCore M17.2 — Catalog Relationships & Editions

M17.2 gives ReleaseCore a first-class model for relationships between releases
and a separate track-level model for recording lineage.

## Why release relationships and recording lineage are separate

A release can be a Deluxe, Expanded, Remaster, Clean, Explicit, Instrumental,
Reissue, Anniversary, Remix, or generic alternate Edition of another release.

That release-level label does **not** prove that every track is the same
recording as the source. Deluxe and anniversary editions can mix unchanged
catalog recordings with bonus tracks, alternate masters, edits, remixes, and
new recordings.

M17.2 therefore stores two layers:

1. `ReleaseRelationship` — how two releases belong together.
2. `TrackRelationship` — which source track corresponds to a current track and
   whether it is the same recording, new/changed audio, or not yet classified.

- Remix edition of

Relationships are directional: the current release is the edition/derivative and
`relatedReleaseId` is its source catalog release.

ReleaseCore blocks self-relations, duplicate source links, cross-shop links, and
direct two-release cycles.

## Track lineage

For each relationship, the admin can map every current track to a source track
and classify the recording as:

- Not classified
- Same recording
- New / changed recording

When a relationship is first created, ReleaseCore conservatively seeds mappings
only when track title/position matching is obvious. Seeded mappings remain
`UNKNOWN`; ReleaseCore never automatically asserts that two tracks are the same
recording.

## ISRC safety

M17.2 is intentionally advisory around identifiers.

ReleaseCore compares the current and source ISRC values and surfaces states such
as:

- Identifiers aligned
- Source ISRC available
- ISRC review
- Needs identifier

It does **not** copy, replace, or remove ISRCs automatically. The current
ReleaseCore Track model still treats existing identifiers as permanent catalog
data, so an edition label alone cannot mutate them.

This gives later distribution and catalog QA workflows an explicit recording
lineage signal without making an unsafe identifier assumption.

## Workspace

Every release now has **Catalog relationships** in its secondary actions.

The dedicated workspace provides:

- current release identity;
- searchable source-release picker;
- relationship type and notes;
- relationship editing/removal;
- track-level recording lineage;
- current/source ISRC comparison;
- incoming/derived releases that point back to the current release.

Candidate source search is bounded and can search title, artist, catalog number,
or UPC.

## Audit history

Relationship and lineage changes create local `SubmissionEvent` records:

- `CATALOG_RELATIONSHIP_ADDED`
- `CATALOG_RELATIONSHIP_UPDATED`
- `CATALOG_RELATIONSHIP_REMOVED`
- `RECORDING_LINEAGE_UPDATED`
- `RECORDING_LINEAGE_REMOVED`

No Shopify API call is required for this workspace.
