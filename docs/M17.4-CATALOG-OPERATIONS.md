# ReleaseCore M17.4 — Corrections, Updates & Takedowns

M17.4 adds a durable catalog-operations workflow for changes that happen after a
release record already exists.

## Catalog operations

ReleaseCore now records three operational request types:

- **Correction** — fix incorrect metadata or identifiers.
- **Update** — deliberately change metadata, artwork, audio, rights, or
  availability.
- **Full release takedown** — record a request to remove the complete release
  from downstream distribution.

Each request keeps:

- category and release/track scope,
- summary and detailed reason,
- optional requested effective date,
- requested-by identity,
- durable status,
- resolution note,
- completion timestamp,
- SubmissionEvent audit history.

Statuses:

`REQUESTED → APPROVED → IN_PROGRESS → COMPLETED`

Requests may also be rejected or cancelled according to the allowed transition
map.

A takedown does **not** delete the ReleaseCore release or its files,
relationships, identifiers, Shopify links, or history.

M17.4 does not directly contact DSPs. The normalized lifecycle model is designed
to feed the future M17.7 delivery/export package.

## Manual catalog-number administration

The new **Catalog Operations** page also adds an Admin-only catalog-number
override.

This is specifically intended for back-catalog imports and corrections.

Admins can:

- assign a catalog number to an older release,
- replace an existing ReleaseCore catalog number,
- use the override even when global numbering remains `AUTO`.

Safeguards:

- catalog numbers are normalized to uppercase,
- duplicate catalog numbers are blocked case-insensitively inside the shop,
- changing an existing number requires `CHANGE CATALOG NUMBER`,
- the previous value is preserved in SubmissionEvent history,
- matching manual numbers advance the relevant automatic sequence so a future
  generated number does not collide.

The override does not change global catalog settings and does not directly
write to Shopify or a distributor.

## High-impact confirmations

- Request full takedown: `REQUEST TAKEDOWN`
- Mark full takedown completed: `COMPLETE TAKEDOWN`
- Replace existing catalog number: `CHANGE CATALOG NUMBER`

These use ReleaseCore's M16.8 production mutation protections.
