# ReleaseCore M16.3 — Save and editor consistency

M16.3 starts by hardening ReleaseCore's two authoritative track metadata editors: **Edit Track Info** and **Bulk Edit Tracks**.

These are the highest-risk catalog editing surfaces because they can change titles, order, language, explicit status, lyrics, and ISRCs.

## Explicit save state

The authoritative metadata forms now expose one of four states:

- **Saved**
- **Unsaved changes**
- **Saving…**
- **Save failed · changes kept**

Save buttons remain disabled until the form has actually been edited.

Relation controls that already use safe autosave behavior remain autosave controls. The UI explicitly identifies that track-artist role changes and credit role/split changes save automatically.

## Navigation protection

Dirty editors now protect both React Router in-app navigation and browser/tab unload.

If the merchant attempts to leave with unsaved metadata, ReleaseCore asks whether to discard the changes.

Successful saves clear the dirty flag. Failed saves retain it.

## Optimistic concurrency

Both track editors send the `Release.updatedAt` value they were loaded with.

`bulkUpdateReleaseTracks` atomically claims that expected release version inside the same database transaction before writing track changes.

If another admin or production operation updated the release after the editor loaded, the save is rejected with HTTP 409 and public code `EDIT_CONFLICT`.

This favors a visible conflict over silently overwriting newer production data.

## Form stability

Edit Track Info now keys its core metadata form to `Track.updatedAt`, not `Release.updatedAt`.

Bulk Edit Tracks keys its form to the loaded track version set.

There is no Prisma migration and no Shopify configuration/scope/extension change.
