# ReleaseCore M16.7 — Performance

M16.7 focuses on keeping ReleaseCore responsive as catalogs grow without changing
workflow semantics.

## Catalog pagination

The largest merchant directory/queue routes are now bounded:

- Releases: 50 per page
- Submissions: 50 per page
- Distribution: 50 per page
- Artists: 75 per page
- Contributors: 75 per page

Each route returns an exact total and renders a shared PaginationBar.

This prevents a large merchant catalog from serializing every release, artist, or
contributor into every page response.

## Narrow list queries

List routes use explicit Prisma `select` payloads where practical rather than
loading complete records.

Submissions uses a filtered relation count for open review items instead of
materializing each review-item row.

## Queue count consolidation

Submissions previously issued six separate status-count queries.

M16.7 uses one `groupBy(status)` query.

Distribution previously issued six separate queue-count queries.

M16.7 uses one `groupBy(distributionStatus, status)` query while preserving the
special APPROVED + NOT_QUEUED behavior.

## Database indexes

M16.7 adds PostgreSQL indexes for Release list/sort paths:

- `(shop, updatedAt)`
- `(shop, lastSubmittedAt)`
- `(shop, distributionUpdatedAt)`

These match the primary catalog, submission, and distribution ordering paths.

## Artist profile Shopify loading

Opening an Artist profile no longer automatically lists Shopify collections or
checks the remote collection on every page request.

By default the page uses the cached ReleaseCore collection association. The
administrator can explicitly choose **Load existing Shopify collections** when
they need remote collection status or the existing-collection picker.

This removes two Shopify Admin API reads from the normal Artist-profile path.

## Data Hygiene candidate indexing

M16.6 duplicate detection originally compared every Artist with every other
Artist, every Contributor with every other Contributor, and every Artist with
every Contributor.

M16.7 builds normalized identifier buckets first and only scores records that
share a duplicate signal. The matching rules and confidence thresholds remain
the same, but ordinary scans no longer perform a full quadratic cross-product.

## Non-goals

M16.7 does not add caching that could serve stale workflow state, does not cache
Shopify writes, and does not weaken exact queue counts.
