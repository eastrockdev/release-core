# ReleaseCore M16.5 — Built-in User Feedback

M16.5 adds a first-party feedback workflow inside the embedded Shopify Admin app.

## Goals

Users can report:

- a problem / bug;
- a workflow improvement;
- a feature request;
- general feedback.

Each report also records an impact level:

- blocking;
- significant;
- minor;
- suggestion.

## Automatic context

When Feedback is opened from the global ReleaseCore navigation, the current **path only** is carried into the report.

ReleaseCore can automatically resolve:

- the current Release ID;
- the current Track ID;
- an explicitly attached Recent System Issue;
- the System Issue request/reference ID.

The service validates release, track, and system-issue ownership against the authenticated shop before saving any association.

## Privacy minimization

Feedback deliberately does **not** collect:

- Shopify staff name;
- Shopify staff email;
- IP address;
- browser fingerprint;
- User-Agent;
- request headers;
- URL query string or hash;
- uploaded files;
- screenshots;
- master audio;
- access tokens or secrets.

User-entered summary/details are passed through the same ReleaseCore diagnostic redaction helper used by production errors, so obvious credentials and signed URL query strings are scrubbed before persistence.

## System Issues integration

Every System Issue card has a **Report this issue** action.

That opens Feedback with the issue preselected. The feedback report stores the validated System Issue ID and a snapshot of its request/reference ID.

## Report history

The Feedback page shows the ten most recent reports from the current shop and deployment profile.

No cross-shop feedback is exposed to merchants.

## Abuse protection

A shop can submit up to 20 feedback reports per hour. This is intentionally generous for testing/support while preventing accidental loops or form spam.

## Deployment

M16.5 includes a Prisma migration:

`20260904033000_m16_5_feedback_reports`

No Shopify scopes, webhooks, extensions, or TOML settings change.
