# ReleaseCore M16.8 — Production Safety

M16.8 adds defense-in-depth around high-impact production writes.

## Startup gate

The production container now runs the existing production-environment validator
before Prisma setup/migrations. The production supervisor validates the
environment again before spawning the web process and operation worker.

This prevents a service with a mismatched ReleaseCore deployment profile,
distribution mode, application URL, or required production configuration from
starting normally.

The production-environment validator also checks `DIRECT_URL` and rejects local
database hosts (`localhost` / `127.0.0.1`) when running production validation.

## Runtime deployment binding

Protected mutations call `assertProductionRuntimeSafety()`.

In production it verifies:

- `RELEASECORE_DEPLOYMENT_PROFILE`;
- the selected deployment profile file;
- `RELEASECORE_APP_DISTRIBUTION`;
- the canonical Railway `SHOPIFY_APP_URL`.

A drifted production service returns a safe 503 instead of performing the write.

## Mutation replay protection

`authenticatedPost()` now sends a fresh `X-ReleaseCore-Mutation-Id` header.

Protected writes claim that ID in `ProductionMutation`, uniquely scoped by:

- shop;
- deployment profile;
- mutation request ID.

If the same POST is replayed with the same mutation ID, ReleaseCore returns 409
instead of executing the high-impact path again.

Protected operations include:

- release approval;
- release rejection;
- reopening a release;
- permanent draft deletion;
- draft-track deletion;
- file deletion;
- Artist → Artist merge;
- Contributor → Contributor merge;
- unused Artist deletion;
- unused Contributor deletion.

M16.2 background publication jobs retain their existing durable idempotency and
profile isolation.

## Explicit destructive confirmation

Rare destructive operations require a typed phrase in the UI and the API checks
the same phrase server-side:

- `MERGE ARTIST`
- `MERGE CONTRIBUTOR`
- `DELETE ARTIST`
- `DELETE CONTRIBUTOR`
- `REOPEN RELEASE`
- `DELETE DRAFT`
- `DELETE TRACK`

This is intentionally separate from authentication. It protects against
accidental destructive clicks and incorrectly wired UI calls.

## Production Safety workspace

Settings → Production Safety shows:

- runtime profile status;
- deployment/distribution checks;
- protected-action behavior;
- recent high-impact mutation claims.

It never returns API secrets, database credentials, worker secrets, or signed
storage URLs.
