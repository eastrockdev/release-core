# ReleaseCore M18.4 — Moderation Controls

## Overview

M18.4 adds two independent Artist Portal moderation controls to Shopify Admin:

1. **Release artist editing lock** — keeps an individual release visible to the artist while making its ReleaseCore workspace read only.
2. **User release-creation restriction** — prevents a specific Artist Portal customer from creating new releases without removing their portal access or existing catalog access.

Both controls are available from **Shopify Admin → ReleaseCore → Moderation**.

## Release artist editing lock

Release locks are stored inside ReleaseCore using an active `ReleaseLifecycleRequest` with:

- `type = PORTAL_EDIT_LOCK`
- `category = MODERATION`
- `scope = RELEASE`
- `status = ACTIVE`

Unlocking resolves the active lock record instead of deleting it so the moderation history remains auditable.

Lock and unlock operations also write `PORTAL_EDIT_LOCKED` and `PORTAL_EDIT_UNLOCKED` submission events.

### Artist Portal behavior

When a release is locked, the portal release-detail response forces:

`release.editable = false`

The existing native Artist Portal read-only rendering then disables or removes editing controls for release metadata, tracks, credits, file uploads, and other release mutations.

The server separately rejects release mutation and upload requests while the lock is active. The read-only UI is therefore not the security boundary.

Shopify Admin ReleaseCore workflows remain editable and are not affected by the artist lock.

## User release-creation restriction

User restrictions are ReleaseCore-owned operational state. No Shopify customer tag or additional `write_customers` OAuth scope is required.

Each change is recorded as a `DataMaintenanceEvent` for the portal customer:

- `PORTAL_RELEASE_CREATION_DISABLED`
- `PORTAL_RELEASE_CREATION_ENABLED`

The most recent event determines the active policy for that customer. Optional moderation reasons are retained in event details.

### Artist Portal behavior

When release creation is disabled:

- every release-type option returned by the portal access payload is marked unavailable;
- the restriction reason is returned with the access state;
- direct `create-release` requests are rejected server-side with `RELEASE_CREATION_DISABLED`.

Existing releases remain visible and editable according to their normal workflow state and any release-specific lock.

## Validation

Run:

```bash
npm run check:m18.4
```

The M18.4 validator checks the admin moderation workspace, ReleaseCore-owned persistence, Artist Portal enforcement, and the native portal read-only rendering contract.
