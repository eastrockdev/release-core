# ReleaseCore M16.4 — Production error handling and Recent System Issues

M16.4 gives production failures a stable operational shape instead of relying on ad-hoc messages or Railway logs.

## Standard error classification

ReleaseCore now classifies operational failures into:

- `VALIDATION`
- `CONFLICT`
- `RATE_LIMIT`
- `AUTHORIZATION`
- `SHOPIFY_USER_ERROR`
- `SHOPIFY`
- `NETWORK`
- `STORAGE`
- `DATABASE`
- `INTERNAL`

Each classified error can carry:

- operation;
- release and track identifiers where known;
- timestamp;
- safe merchant-facing message;
- internal error class/code;
- structured Shopify `userErrors`;
- request/reference ID;
- retryability;
- recommended resolution.

API responses expose only the safe operational fields. Stored `technicalMessage` is never rendered in the admin UI.

## Recent System Issues

A new `SystemIssue` model records deduplicated production failures per shop and deployment profile.

Repeated copies of the same issue increment `occurrenceCount` instead of flooding the database.

The admin now includes:

- a System Issues navigation item with open-count badge;
- an Operations metric for open system issues;
- a Recent system issues section in Operations;
- a dedicated `/app/system-issues` history page;
- manual Mark resolved;
- automatic reopen if the same fingerprint happens again;
- automatic resolution when a previously failed background job later succeeds.

## Background jobs

M16.2 terminal background-job failures are now written to System Issues with a job reference.

A successful retry resolves the matching open issue.

## Shopify errors

The error layer preserves structured Shopify user errors when a server operation attaches them. M16.4 also upgrades common Shopify product/bundle mutation failures to attach the original user-error records rather than flattening them into one string.

## Data safety

System Issues stores only redacted diagnostic text. Signed URL query strings, bearer credentials, tokens, secrets, passwords, and authorization values are scrubbed before persistence.

No uploaded files, form bodies, master audio, access tokens, or customer data are captured.
