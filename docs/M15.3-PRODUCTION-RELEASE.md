# ReleaseCore M15.3 production release gate

M15.3 is the final release-candidate hardening gate for the current ReleaseCore train. It does not replace manual Shopify review, Railway, or storefront testing. Its purpose is to make every repository, configuration, environment, and endpoint prerequisite explicit and repeatable.

## 1. Repository freeze

From the exact commit intended for production:

```bash
npm ci
npm run check
git diff --check
git status
```

The working tree must contain no accidental source/config changes.

## 2. Static production-readiness gate

```bash
npm run check:m15.3
```

This validates the production Docker contract, Shopify production configuration, stable API version, webhook subscriptions, deployment-profile isolation, profile-aware production verifier, environment validator, Track Editor route architecture, and current release documentation.

## 3. Production environment contracts

Run these against the environment variables of each Railway service.

Generic ReleaseCore:

```bash
npm run check:production-env:releasecore
```

East Rock:

```bash
npm run check:production-env:east-rock
```

The validator never prints secret values. It checks that required variables exist and that the public identifiers/URLs match the selected deployment profile.

## 4. Deploy the web application

Railway deploys the ReleaseCore web application. Shopify CLI does not deploy the web server.

Generic service:

- `SHOPIFY_APP_URL=https://releasecore-web-production.up.railway.app`
- `RELEASECORE_DEPLOYMENT_PROFILE=releasecore`
- `RELEASECORE_APP_DISTRIBUTION=app_store`

East Rock service:

- `SHOPIFY_APP_URL=https://releasecore-er-production.up.railway.app`
- `RELEASECORE_DEPLOYMENT_PROFILE=east-rock`
- `RELEASECORE_APP_DISTRIBUTION=single_merchant`

Both services require the production database, encryption key, R2 master-storage variables, and their own Shopify API credentials.

## 5. Verify live endpoints

After Railway finishes:

```bash
npm run verify:production:releasecore
npm run verify:production:east-rock
```

Both verifiers check public pages, install guidance, HTTPS, and invalid-HMAC rejection for compliance/uninstall webhooks.

## 6. Shopify configuration release

The M15.3 config uses the stable `2026-07` webhook API version.

Create the generic App Store review version without releasing it first:

```bash
shopify app config use releasecore
shopify app deploy --no-release --version releasecore-m15-3-review
```

Inspect the generated version in Shopify Dev Dashboard before release.

For East Rock, select the East Rock config and deploy its configuration separately:

```bash
shopify app config use east-rock
shopify app deploy --no-release --version releasecore-east-rock-m15-3
```

Do not use `--allow-deletes` unless a deliberate extension/config deletion has been reviewed manually.

## 7. Mandatory manual evidence

Before production sign-off, record evidence for:

- exact Git commit deployed to each Railway service;
- `npm run check`;
- both production-environment validations;
- both live endpoint verifiers;
- released Shopify version(s);
- active compliance/uninstall/order webhook subscriptions;
- signed `customers/data_request`, `customers/redact`, and `shop/redact` deliveries;
- fresh-store generic ReleaseCore install;
- Chrome incognito/session-token usage;
- 65+ minute idle uninstall and reinstall;
- Theme Editor deep links and all storefront blocks;
- Artist Portal customer/artist access isolation;
- Single ISRC correction through Edit Track Info page;
- EP/Album existing-track linking;
- audio preview generation;
- Sync Health + targeted recovery;
- complete-release publication orchestration;
- East Rock compatibility metafields;
- App Store protected customer data approval;
- support/emergency contacts;
- listing icon, screenshots, screencast, reviewer credentials.

## 8. Sign-off rule

M15.3 is complete only when:

1. all automated gates pass;
2. both production services pass their applicable endpoint/environment checks;
3. the exact Shopify configuration versions are inspected and released;
4. all manual evidence is recorded.

Do not treat a successful build alone as production sign-off.
