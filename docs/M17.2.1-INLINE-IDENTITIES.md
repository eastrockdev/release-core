# ReleaseCore M17.2.1 — Inline Identity Creation & Track Save Repair

M17.2.1 is a focused workflow improvement before M17.3.

## Inline artist creation

Edit Track Info now supports Existing artist / New artist without leaving the
track.

New artist mode keeps the role selector visible and replaces the directory
dropdown with an Artist name field. One server transaction creates the Artist
directory record and assigns it to the current track.

## Inline contributor creation

Credits & Splits now supports Existing contributor / New contributor.

New contributor mode keeps the role and publishing split controls visible and
replaces the contributor dropdown with a Contributor legal name field. One
server transaction creates the Contributor and credits the current track.

More detailed contributor identity data such as stage name, PRO, IPI, publisher,
email, and notes can still be completed later from the Contributor workspace.

## Duplicate protection

Inline creation checks for an exact case-insensitive existing identity first.

When found, ReleaseCore refuses to create another record and tells the admin to
switch back to Existing mode.

## Dedicated Track save conflict repair

The dedicated Track editor previously used Release.updatedAt as its optimistic
version token. That token covers the entire release, so unrelated release
activity could advance it and make a normal language/title/lyrics save report:

"This release changed in another session."

even when no second editor existed.

M17.2.1 changes dedicated single-track saves to claim Track.updatedAt instead.

The server performs that track-version claim inside the same transaction as the
metadata update. A real concurrent edit to the same Track is still rejected.

The multi-track Bulk Editor retains Release.updatedAt because reordering and
multi-track saves require a release-wide atomic version claim.
